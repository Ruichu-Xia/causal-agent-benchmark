Research proposal

CausalAgentBench: A Verifiable Causal-Agent Benchmark and RL Environment

A benchmark and RL environment for evaluating and training causal reasoning in tool-using agents.
The idea

Generate the data, so the answer is known

Causal questions have no ground truth on real data. So we build the data from a hidden causal model — and that model becomes the answer key.
SCM-generated table → agent ranks drivers → SCM verifies. Objective, automatic, unlimited.
Contribution: a causal-agent benchmark with an exact, closed-form verifier — and, called as a reward, the very same generator is an RL environment that trains the skill, not just scores it. Unlimited instances, a dense reward, reproducible rollouts.
The task

Rank the drivers — and know when you can't

The agent sees a named table and tools. For each candidate driver it must decide what to adjust for and whether the effect is even identifiable, then rank the identifiable drivers by causal effect — demoting the confounded decoy to the bottom, and abstaining where no adjustment can recover the effect.
InputNamed CSV (outcome, candidate drivers, covariates) + a code sandbox
DeliverablePer driver: an adjustment set + an identifiability flag. Overall: a ranking of the identifiable drivers, decoy last.
ScoreThree axes — ranking, identification, and calibration (abstention). Not one number; detailed below.
Hard partDeciding what to adjust for — and when you can't identify the effect at all. Not computing a number.
What's inside an instance

A confounded causal graph

A shared cause makes drivers look effective when they aren't. A decoy has zero real effect but correlates with the outcome. The agent must see through both.
Amber = confounding. Red = real causal effect. Decoy correlates with Y but has no arrow to it.
The key instrument

Reasoning, or just reading the labels?

Every instance has hidden causal roles — a true driver, a confounded decoy, a shared cause. Naming is the map from those roles to the column labels the agent sees. We hold the graph and the numbers byte-identical and change only that map. The gap between the two settings shows whether a model reasoned about the data or just recited its priors from the labels.
ALIGNED

Label points the right way

The behavior whose name screams “driver” — say daily_active_minutes for retention — really is the top driver. Guessing straight from the name lands the ranking, so a high score here proves little on its own.

MISALIGNED

Label points the wrong way

The same intuitively-strong name, daily_active_minutes, is now pinned to the decoy: zero real effect, but correlated with retention through a shared cause. Trust the label (or the raw correlation) and you rank it #1; only a model that adjusts for the confounder sees the effect is ~0 and sends it to the bottom.

What exactly flips: only the label↔role assignment. Across an aligned/misaligned pair the topology, the edge weights, and the noise are identical — the evocative name simply moves off the true driver and onto the zero-effect, confounded decoy (while a bland name moves onto the real driver). A model that answers from names alone scores high on aligned instances and collapses on misaligned ones; the size of that collapse is the reasoning-vs-recitation metric.
The aligned–misaligned gap = how much a model leans on names instead of reasoning.
The metric is appropriate reliance. We don't simply penalize using the names — we score whether the agent uses a label when it is informative (aligned) and overrides it when the data contradicts it (misaligned). Prior work only neutralizes names to dodge the “causal parrot”; the newest agentic benchmark (CausalDS) holds them aligned by construction, which is partly why it finds identification nearly solved. Dialing names to misaligned is what turns that apparent competence back into a measurable gap.
Difficulty knobs

One generator, tunable hardness

The graph shape is fixed; these dials set how hard each instance is.
KNOB 1

Confounding

Shared cause strength. The floor — without it, correlation = causation.

KNOB 2

Decoy

Zero-effect variable that correlates with Y. Must be demoted.

KNOB 3

Mediation

Drivers that cause each other. Turns single-lever ranking into a chain.

KNOB 4

Naming

Aligned vs. misaligned. Reasoning vs. recitation.

New instance class · Knob 5

The confounder you can't see

One confounder is generated and then withheld from the CSV. The drivers it touches become non-identifiable from observed data — no adjustment recovers their effect. This is the single hardest case in applied causal inference, and the correct answer stops being a ranking.
B's confounder is in the data → adjust for C → identifiable. A's backdoor path A←U→Y runs through a variable you never see → no adjustment closes it.
WHAT'S EXACT

The oracle still knows

Effects are computed over the full SCM, latents included, so the true ranking always exists. Identifiability is a separate deterministic query on the observed-variable marginal.

CORRECT ANSWER

Abstain, don't guess

For a touched driver the right output is “not identifiable — I'd need an instrument or can only bound it,” and that is scored as correct, not as failure.

SCOPE

Backdoor now, full ID later

v1 restricts to the backdoor case, where the check is “does some observed set block all backdoor paths.” The general ID algorithm (Tian–Pearl / Shpitser) is a heavier optional extension.

Where the two ceilings provably diverge: on these instances the SCM oracle sits above the best answer any agent could reach from the observed data. Grading abstention is the only way to reward an agent for correctly landing on that lower ceiling instead of fabricating a number to reach the higher one.
How the SCM is made

Random sampling, inside a fixed scaffold

The scaffold is fixed; the graph is not. Prior work samples a whole random DAG and reads roles off it. We instead fix the roles and the guarantees — a confounder, a wired-zero decoy, at least one identifiable driver — and randomize everything else: the wiring within those roles, the weights and noise, and which name and column position each role gets.
Linear-Gaussian → effects are exact from one matrix inversion. Verify-reject keeps only sound instances.

Multi-treatment knob

Treatment→treatment edge density. Zero = simple; higher = mediation.

Decoy is constructed

Its zero effect is wired, never left to random weights.

Reject bad instances

Discard the trivially solvable (raw correlation already ranks them) and the malformed. Deliberately non-identifiable instances (Knob 5) are kept — there, abstention is the gold answer.

Why not a fully random SCM? Three of our instruments only exist over a controlled family: the naming axis needs control over which node is driver vs. decoy independent of its label; calibration needs a balanced mix of identifiable and non-identifiable instances; the identification score needs a valid adjustment set guaranteed to exist. And random isn't automatically harder — Beware of the Simulated DAG (Reisach et al., NeurIPS 2021) showed that i.i.d.-parameter sampling makes the causal order readable off marginal variance (varsortability), so a variance-sorting baseline can “win” with no causal reasoning — and the pattern can survive standardization (R²-sortability). So we fix the contract, randomize the realization, and prove on the sampled distribution that the trivial exploits still fail.
The scoring, revised

Three numbers, never blended

A single rank correlation rewards a confident guess that happened to land. So the agent returns more than an order — and grading splits into three independent axes, each measuring a different skill.
One artifact, three axes. Ranking and identification measure competence; calibration measures knowing when to stop.
RankingKendall-τ vs. the true total-effect order, computed over the identifiable drivers only.
IdentificationFraction of drivers whose chosen adjustment set is a valid backdoor set in the true DAG (a deterministic d-separation check), with a hard penalty for bad controls — mediators, colliders, descendants of the driver.
CalibrationAbstention accuracy as a balanced two-way classification (identifiable vs. not), with symmetric penalties so false abstention costs as much as false confidence.
Validity, not exact match — and a clean reasoning/execution split. Several adjustment sets can be valid, so a different-but-valid set isn't punished; only invalid sets and bad controls are. And because the true τ is closed-form, error decomposes exactly: on a driver the agent identified validly, any estimate error (|estimate − true τ|) is an execution / tool-use fault — a botched estimator, a mis-wired treatment/outcome, a misused causal library — never an identification fault. So causal reasoning (did it pick a valid design?) and tool-execution fidelity (did it run that design correctly?) are measured apart — a split CausalDS's Monte-Carlo ground truth and CRB's real-data gold can approximate but not make exact.
Is the benchmark sound?

Trivial approaches must fail

A score should mean causal reasoning, so every instance is screened two ways: shortcuts that must fail (no cheap trick scores well) and soundness checks (the gold answer really is gold).
Oracle (full)Given the true graph + the correct adjustment, the ranking  must ≈ 1.0  — proves the answer is reachable
CorrelationRank drivers by raw correlation with Y  must fail  — if it succeeds, confounding is too weak
sortnregressThe variance-scale exploit  must fail  — and still fail after standardizing (R²-sortability)

Three more checks are easy to misread — here is exactly what each one is, and what “fail” means:

CHECK · NAMING

Name-blind pipeline

A strong statistical pipeline that sees the numbers with every column name masked (X1, X2, …). With names hidden it can't tell which observed variable is the confounder to adjust for — Gaussian data can't separate a confounder from a mediator on its own. What must fail: it can't rank correctly, and because it never sees names it scores identically on an aligned instance and its misaligned twin. So it does two jobs — it shows the labels carry load-bearing causal assumptions (pure stats can't substitute), and, having a zero aligned–misaligned gap by construction, it proves any gap a real model shows comes from name use, not a data artifact.

CHECK · SOUNDNESS

Oracle, observed-only

On latent instances (Knob 5) we run the oracle — which knows the true graph — but restrict it to the observed columns only. What must fail: even it must return “no valid adjustment set,” because the backdoor path runs through the withheld confounder and nothing observed can block it. This confirms the instance is genuinely non-identifiable — so abstention is the gold answer because no method could recover the effect, not because our method is weak.

CHECK · ANTI-OVERFIT

Held-out discovery

A strong causal-discovery algorithm kept deliberately outside the baseline set we reject against — PC, GES, or NOTEARS — run on the data. What must fail: it must not recover the ranking on the hard, identifiable instances either. We reject instances until correlation, sortnregress, and the name-blind pipeline fail; a distribution tuned to beat only those three could still fall to a fourth method. A held-out one failing too keeps “the task needs reasoning” honest.

Two non-negotiables: confounding strong enough that raw correlation fails; and labels that are load-bearing — the name-blind pipeline fails whether names are aligned or not — otherwise the task is solvable by tools with no causal reasoning at all.
Why this holds together

The naming tension, dissolved

The earlier figure assumed a good reasoner gets misaligned instances right, while the validation assumed pure statistics can't solve them. Both can't be true at once — and the three-axis scoring is what removes the contradiction.
ON IDENTIFIABLE INSTANCES

Measure structure recovery

The identification score asks whether the agent chose a valid adjustment set — the thing correct names help supply and a name-blind pipeline cannot. Reasoning shows up here, directly.

ON MISALIGNED / LATENT INSTANCES

Measure calibrated abstention

The correct behavior is recognizing the names can't be trusted and the data is ambiguous — not producing a ranking that is not recoverable. Scored as calibration, not accuracy.

The payoff: the benchmark no longer needs the impossible claim that a strong reasoner scores well on instances whose answer isn't in the data. Competence and calibration are measured on the instances where each is actually well-defined.

What sets this apart. Recent benchmarks (CausalDS, CausalProfiler) also sample SCMs and score abstention — we're not claiming to have invented SCM-based causal evaluation. We claim a specific, unoccupied combination: an exact closed-form verifier, a ranking of competing drivers with an engineered confounded decoy, the aligned/misaligned naming axis as a measurement, and — alone in this table — a first-class RL environment rather than an evaluation-only suite. The exactness and cleanliness are the point: they're what make a trustworthy reward signal and unlimited, reproducible rollouts possible.
And it surfaces a failure broad benchmarks miss. CausalDS reports causal identification looking largely solved — but that's an aggregate: it holds on easy adjustment cases and breaks on the hard ones. In its own results, models correctly see “no backdoor set” on instrumental-variable scenes, then wrongly claim the instrument identifies the population effect (four of six models on its running IV scene); front-door and forbidden-control cases split the field too. We target exactly those hard-identification cases and misalign the names — and the “solved” impression collapses.
The harness

Swap the model. Swap the whole agent.

The environment grades an artifact — the ranking plus each driver's adjustment set and identifiability flag — never a process. So any model or any custom agent workflow plugs in, and the score is computed the same way. Three layers, clean contracts.
The environment scores the answer regardless of how it was produced — the SWE-bench "bring your own agent, we grade the artifact" contract.
SWAP THE MODEL

One line

The default loop calls a single chat(messages, tools) endpoint. Point it at GPT, Claude, or a local model — the loop is model-agnostic.

SWAP THE AGENT

One method

Custom workflows subclass solve(instance) → answer and do anything inside — own tools, own control flow, own model. The default loop is just one implementation.

TOOLS

Provided, not forced

Exposed both as sandbox functions (any code-writing agent imports them) and as a tool-call schema. Bring your own instead if you like.

Graded on causal artifacts, not API calls. The agent emits the causal objects — the graph, the identification strategy, each adjustment set, the estimate, and a refutation verdict — and every one is checked against the exact SCM. Correctness is tool-agnostic: DoWhy, EconML, causal-learn, or hand-written code all count equally, so the score rewards getting the causal object right, not fluency with one library's API.
Tool access is a reported setting, not just plumbing. Scores are comparable only within a tier: full-tools (prebuilt causal kit) · sandbox-only (bare Python) · no-tools (pure reasoning). The tier changes what is measured — no-tools tests reasoning; full-tools tests reasoning + execution — so the harness records it with every run.
The core contribution

Not just a benchmark — an RL environment for causal agents

Almost every causal benchmark — CausalDS, CauSciBench, CRB, CausalProfiler — is built to score agents. This one is built to train them. Report the verifier's score and it's an evaluation; use it as reward and the same generator is a training environment, with unlimited fresh instances and no human labeling in the loop.

An exact, dense reward

Ranking quality vs. true τ, a dense signal for choosing a valid adjustment set, and credit for correct abstention — all in closed form, because we own the SCM. No learned reward model, no noisy proxy.

Cheap, reproducible rollouts

The generator emits fresh instances on demand from a seed, so training data is unlimited and every run is reproducible. Cleanliness isn't cosmetic — it's what makes RL against this env cheap and stable.

The trap to avoid

Don't reward “close the gap” — a model closes it by ignoring names. Reward using names when they help, then overriding them when the data disagrees — the appropriate-reliance signal.

Keep eval & training separate. A model trained here is judged on transfer (held-out structure, then semi-synthetic, then RCAEval) — never on this env's own score. The environment claim stands today; the transfer result is Paper 2's to prove.
Where it pays off

Two applications, one capability

Product analytics

Which behavior, if promoted, lifts retention? The confounded-decoy ranking task, verbatim. (Adobe Acrobat — the motivating setting.)

Root-cause analysis

Which factor caused the failure vs. merely co-occurred? Same task — the bridge to reliability and safety-critical systems.

These are the application, not the contribution — which is the verifiable benchmark and the capability it measures and trains.
Potential extension

From static rows to time series

The same SCM → agent → verify loop, generalized to a linear structural VAR. Drivers, confounder, decoy, and Y evolve over time instead of one static row — closer to clickstream, vehicle telemetry, and biosignal data.
KNOB 6

Lag obfuscation

True driver's effect appears several steps later; decoy correlates at lag 0. Naive same-timestep correlation points at the wrong variable — the core RCA failure mode.

KNOB 7

Feedback loops

Y at t shapes a driver at t+1 (e.g. past clicks shape future recommendations). A naive agent reads this as forward causation.

KNOB 8

Shared trend

Two unrelated series drift together over a session or product cycle — the temporal analog of the existing confounder knob.

Why it's not just realism: Paper 2 transfer-tests on RCAEval, which is telemetry time-series — while v0/v1 train on static rows. A time-series generator variant closes that train/transfer gap instead of leaving it a confound in our own eval.
Keep it exact: generalize τ = (I−W)⁻¹−I to an impulse-response function from VAR coefficients — still closed-form. Stay linear-Gaussian; resist irregular sampling / nonlinear dynamics, or the SCM verifier stops being exact. Frame neural-signal instances as structurally analogous to biosignal monitoring, not as modeling real neural dynamics.
